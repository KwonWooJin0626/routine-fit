# 자기개발 중심 개편 · 2026-10-27

## 사용자 흐름

1. 짧은 기능 안내와 정보 저장 동의.
2. 이름 → 선택적 키·몸무게 → 수면 범위 → 주간 운동 시간 범위 → 좌식 시간 범위 → 현재 영양제 여부·성분 다중 선택.
3. 기본 루틴 즉시 제공. 첫 추천 뒤 InBody 등록이나 영양 화면으로 자동 이동하지 않는다.
4. 선택적 목표·가능 시간·집중 시간·실천 장벽 질문으로 루틴 정밀화.
5. 고정 일정 → 날짜별 일정 → 해당 주의 일정 기반 생활패턴 분석. 작성한 날 수와 예정 시간임을 표시한다.
6. 실제 실행 체크는 계획과 분리한다. 미기록을 실패로 처리하지 않는다.
7. 수면 체크인과 컨디션·영양은 선택 기능이다. 주간 계획이 없어도 기본 영양 정보와 주의사항을 볼 수 있다.
8. 아침·저녁 자체 작성 글귀, 선택적 한 줄 회고. 날짜·시점별 문구는 일정하게 유지한다.

## 데이터와 호환성

- `answers.basic`은 범위 응답을 보관한다. 기존 상세 숫자 필드는 기존 형식 호환을 위해 남아 있지만 새 기본 추천의 분석값으로 사용하지 않는다.
- 기존 계정은 정확한 과거 응답을 지우지 않고 `origin: legacy` 요약을 추가한다. 다음 저장 시 함께 보관된다.
- 오늘 실제 수면 미입력은 `checkin.sleepKnown: false`로 구분한다. 내부 호환 필드의 임시 숫자를 실제 수면 기록처럼 표시하지 않는다.
- 새 기본 프로필은 자기개발 루틴을 사용하며, 식사 빈도 등 호환 기본값으로 영양제를 순위 추천하지 않는다.
- 기존 직접 추가 루틴·완료 기록·이전 일정·InBody·음식 프로필은 보존한다.
- `growth`는 글귀 숨김과 최근 90개 날짜의 회고를 저장한다.
- `sleep_profiles`, `sleep_records`, `sleep_deliveries`는 계정에 종속되며 전체 정보 삭제 시 연쇄 삭제된다. 수면 조회 시 90일 이전 기록을 정리한다.
- 전체 내보내기는 기존 상태와 별도로 `sleepArchive`를 포함한다. 기존 가져오기 기능은 상태 본문을 복구하며, `sleepArchive`는 수면 기록 보관용이다.

## 수면 기록의 의미

- 목표 시각, 최초 체크인 시각, 수정 가능한 자기보고 시각을 구분한다.
- 취침 준비는 수면 시작과 다르다. 두 체크인의 차이를 실제 수면시간으로 환산하지 않는다.
- 취침 준비의 `alarm-setting` 방식은 사용자가 직접 버튼을 누르는 기능이다. 기기 알람을 읽지 않는다.
- 날짜와 반복 요일은 기상일·한국 시간 기준이다. 취침 목표가 23시, 기상이 07시라면 전날 밤과 다음 날 아침을 하나의 기상일로 묶는다.
- 반복 클릭은 최초 확인 시각을 유지한다. 자기보고 수정은 별도 `actualAt`과 수정 시각을 남긴다.

## Resend 설정 대기 상태

사용자는 설정 전 웹 체크인만 사용하도록 선택했다. 실제 메일을 보내거나 유료 서비스·예약 작업을 생성하지 않았다.

준비가 끝나면 서버 전용 환경변수에 다음 값을 등록한다. 키는 채팅·코드·Git에 넣지 않는다.

| 변수 | 용도 |
| --- | --- |
| `RESEND_API_KEY` | Resend 발송 키 |
| `SLEEP_EMAIL_FROM` | 인증한 도메인의 발신 주소 |
| `SLEEP_APP_URL` | 운영 HTTPS 원점 |
| `SLEEP_TOKEN_SECRET` | 메일 확인 링크 서명용 임의 비밀값, 최소 32바이트 권장 |
| `CRON_SECRET` | 예약 실행 인증용 별도 비밀값, 최소 32바이트 권장 |
| `SLEEP_EMAIL_SCHEDULER_ENABLED` | 예약 실행 연결 후 `true`로 설정 |

예약 실행기는 매분 `GET /api/cron/sleep`을 `Authorization: Bearer <CRON_SECRET>` 헤더와 함께 호출해야 한다. 응답에 `nextCursor`가 있으면 같은 실행에서 해당 커서로 이어 호출한다. 비밀값을 URL 쿼리에 넣지 않는다.

Vercel Hobby Cron은 하루 한 번·시간 단위 정밀도 제한이 있으므로 이 용도로 활성화하지 않았다. 분 단위 실행이 가능한 예약 서비스 또는 적절한 Vercel 요금제에서 별도로 연결해야 한다. 요금제를 자동 변경하지 않는다.

설정 완료·재배포 후에도 사용자가 수면 화면에서 메일 알림을 직접 켜야 한다. 인증된 Clerk 기본 이메일만 수신자로 저장한다. 계정의 이메일이 바뀌면 수면 알림 설정도 다시 저장한다.

예약 발송은 목표 시각 이후 10분 안의 작업만 처리한다. 지난 알림을 한꺼번에 보내지 않는다. DB 발송 키와 Resend 멱등 키로 중복을 막고, 짧은 유효 구간 내 다음 예약 실행에서 실패 작업을 재시도한다. `sent`는 발송 서비스 접수 상태이며 실제 전달 보장은 아니다.

메일 링크의 GET 화면은 기록을 생성하지 않는다. 로그인한 사용자가 명시적으로 POST 확인해야 하며, 계정·설정 버전·만료·발송 상태를 확인하고 한 번만 사용한다. 알림 중지나 설정 변경은 이전 확인 링크를 무효화한다.

## 검증

```sh
npm test
npm run typecheck
node scripts/test-sleep-db.mjs
npx next build --webpack
```

DB 통합 검사는 `.env.local`의 개발 DB에서만 합성 계정을 생성하고 정리한다. 운영 사용자의 데이터를 읽거나 수정하지 않는다. 실제 메일 전달 검사는 설정이 완료된 뒤 별도로 수행해야 한다.

표준 화면에서는 질문과 이동 버튼이 한 화면에 들어오도록 배치하며, 글자 확대·키보드·아주 작은 화면에서는 내용이 잘리지 않도록 스크롤을 허용한다.

## 글귀

현재 문구는 `lib/daily-words.ts`의 자체 작성 문구만 사용한다. 지정된 네이버 블로그는 본문과 재사용 권한을 확인하지 못했으므로 가져오거나 저장하지 않았다. 외부 문구는 원저자·원출처·사용 권한을 확인한 뒤 추가한다.
