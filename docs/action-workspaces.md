# 실천 체크 / 계획 세우기

2026-11-10. 메뉴 기준을 날짜에서 사용자 행동으로 변경한다. 기존 state, 일정 occurrence ID, 루틴 ID, 복용 slot ID, 실제 활동 journal을 그대로 사용하며 데이터베이스 스키마 변경은 없다.

## 정보 구조

- 실천 체크: 선택한 날짜의 일정·할 일·루틴·등록한 제품 복용·수면 체크인. 기본 진입은 오늘. 전체/일정·할 일/루틴/건강관리 필터를 제공한다.
- 계획 세우기: 주간·하루 일정, 제목부터 작성하는 To-do, 고정·추가 일정, 블록 보관함, 활동 목표, 루틴·영양 정보. 선택한 날의 실천 체크로 이동한다.
- 성장 기록: 생활패턴 분석, 주간 돌아보기. 기존 계획/실제 구분 유지.
- 강아지: 상태·성장·상호작용. 실제 활동 기록은 입양과 독립적이다.
- 내 정보: 기본 정보, 제품·복용 시간, 수면 목표·알림, 취향·신체 기록·계정 설정. 체크 기능으로 돌아가는 경로를 제공한다.

## 날짜와 기록

- 계획 → 체크, 체크 → 계획 전환 시 날짜를 전달한다. 날짜 입력에는 기존 date/time 필드와 같은 input/change 처리를 적용한다.
- 과거 일정과 루틴은 선택한 원본 날짜에 기록한다. 루틴 저장 시 오늘을 삭제하거나 같은 과거 날짜를 중복 추가하지 않는다.
- 미래는 미리보기다. 일정/루틴/복용/수면/직접 활동 기록을 완료할 수 없다.
- 시간 없는 할 일의 완료는 실제 체크한 날을 기준으로 하므로 체크 화면의 신규 완료·취소는 오늘만 제공한다. 기존 과거 완료 사실은 완료한 날짜에 표시한다.
- 직접 수면 체크인은 현재 시각을 기록하므로 오늘만 허용한다. 지난 날짜에서는 기존 체크인의 실제 시각을 수정할 수 있다. 목표 설정과 기록 화면은 분리한다.
- 단순 완료는 실제 시간이나 XP를 만들지 않는다. 실제 수행은 기존 확인 대화상자와 API의 중복·겹침·시각·계정 소유권 검증을 거친다.
- 완료한 일정·루틴은 주 목록에서 내려 완료 기록 팝업에서 확인/수정/되돌리기한다. 할 일 역시 되돌릴 수 있다.
- 계획에 없던 활동은 실제 journal에 직접 기록한다. 사용자가 원하면 내 블록으로 저장한다. 저장은 계획 보관함만 추가하며 실제 기록·보상은 복제하지 않는다. 시간·분량은 수정 가능한 보관함 기본값이다. 부담 출처는 미확인으로 둔다.

## UI와 호환성

- 모바일 4개 체크 필터, 줄바꿈이 적은 하단 5개 메뉴, 짧은 목록과 더 보기, 상세 팝업을 사용한다.
- 일정 상세 열기와 완료 체크 버튼은 별도다. 카테고리 색을 일정 행 테두리에 재사용한다.
- 계획의 주간/하루 선택은 브라우저에 기억한다. 저장값이 없으면 모바일은 하루를 기본으로 한다. 시간표 편집은 명시적으로 연다.
- 기존 `?view=today`, `planner`, `report`, `supplements`, `inbody`, `settings` 링크를 유지한다. `?view=sleep`은 실천 체크의 건강관리로 연결한다.
- 기존 질문·답변·일정·루틴·실제 기록·제품·수면·강아지 데이터는 지우거나 초기화하지 않는다. Resend는 기존처럼 설정 전 웹 체크인만 사용한다.

## 검증

타입 검사, 엔진/상태/날짜별 기록 테스트, 배포용 빌드, 개발용 임시 Clerk 계정으로 API→Neon 저장/복원, 브라우저에서 날짜 전달·완료/되돌리기·필터·수면·모바일 가독성을 확인한다. 운영 사용자 데이터에는 검증용 완료 기록을 추가하지 않는다.
