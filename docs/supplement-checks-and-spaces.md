# 통합 체크와 일정 기반 영양 안내 · 2026-11-09

## 사용자 흐름

1. 계획표에 일정을 등록한다. 첫 화면은 주간 날짜 요약과 선택 날짜의 일정이며 전체 시간표·드래그 편집·To-do·블록 보관함은 버튼으로 연다.
2. 컨디션·영양에서 일정 기반 영양 정보를 바로 본다. 추가 추천 질문은 없다. 기존 식단·알레르기·유당 정보는 검색 방향에 재사용한다.
3. 추천 성분의 iHerb 검색 버튼으로 이동하거나 복용 계획에 등록한다. 상품명·복용량·요일·시각은 사용자가 라벨을 확인해 입력한다. 여러 시간대, 식사·운동·취침 기준 간격, 시작/종료일을 지원한다.
4. 오늘의 루틴 화면에서 루틴과 영양제 복용을 함께 체크한다. 두 진행 수치는 구분한다. ‘건너뜀’, ‘기억나지 않음’, 실제 시각·복용량 수정, 기록 취소를 지원한다.
5. 주간 리포트에서 오늘까지의 복용·건너뜀·미기록·기억나지 않음 수를 구분한다. 복용량이나 제품 수로 강아지 XP 또는 건강 개선 점수를 만들지 않는다.

## 저장과 날짜

- 인증된 사용자별 `supplement_journals`를 AppState와 별도로 저장한다. 프로필 행 잠금과 revision 비교로 다중 창 충돌을 거절한다. 루틴 재생성은 복용 계획·기록에 영향을 주지 않는다.
- 한국 시간 기준 제품×계획 날짜×시간대별 하나의 기록이다. 최근 90일만 기록하며 미래는 미리보기다. 과거 복용에는 실제 시각이 필요하다.
- 기록 당시 제품명·성분·계획량·계획 시각을 스냅샷으로 보존한다. 제품 이름·일정 변경이나 일시중지는 과거 사실을 덮어쓰지 않는다. 기록 정정은 같은 키를 갱신한다.
- 동일 출처·Clerk 세션·입력 길이/스키마·iHerb URL 검증. 조회 응답은 private/no-store. 계정 초기화 시 FK cascade로 함께 삭제한다.
- 데이터 내보내기에 최신 `supplementJournal`을 포함한다. 기존 AppState 가져오기 화면은 이 별도 저널의 복원 기능을 아직 제공하지 않는다.

## UI 원칙

오늘·계획·분석·수면·영양·리포트·InBody·설정에 같은 타이포/간격/카드 규칙을 적용했다. 요약과 주요 동작을 먼저 두고 기록·설명·참고 자료는 펼쳐 본다. 루틴은 초기 3개 표시 후 더 보기로 전부 확인하며 추천 결과 자체를 삭제하지 않는다. 모바일은 오늘/계획/기록/전체 하단 내비게이션을 사용한다. 작은 화면에서 모든 상세 내용을 강제로 한 화면에 축소하지 않는다.
