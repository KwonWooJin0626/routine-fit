# 일정 중심 영양 가이드

## 진입

- 신규 가입: 저장 동의 → 닉네임 → 계획표. 신체·수면·운동·현재 영양제 기초 질문은 선택 경로로 남긴다.
- 오늘 화면: 접힌 영양 가이드. 계획표: 선택 날짜의 가이드. 컨디션·영양: 날짜 선택과 상세 성분 안내.
- 영양정보 미동의 시 관련 분석·카드를 표시하지 않는다.

## 규칙

`lib/schedule-nutrition.ts`는 무료 로컬 규칙으로 실행한다. 새로운 외부 API나 LLM 호출, DB 테이블이 필요하지 않다.

- 주간 반복, 제외일, 종료일, 전날 야간 일정, 기본 하루 설정의 기존 이벤트를 반영한다. `plan-`으로 가져온 이벤트는 중복 집계하지 않는다.
- 등록된 휴식은 활동 시간에서 제외하고 겹친 구간은 합집합으로 센다. 미진행으로 표시한 일정은 제외한다.
- 운동 카테고리의 명확한 제목만 종류를 분류한다. ‘헬스’는 미확인이다. 다른 카테고리의 운동 단어·예상 정신/육체 점수로 영양소를 추정하지 않는다.
- 운동 종류는 선택적으로 확인·수정하고 원본 groupId와 제목에 연결해 반복 배치에 재사용한다. 제목이나 카테고리가 바뀌면 이전 해석을 강제하지 않는다.
- 근력/유산소 일정: 단백질의 기능 및 식사 준비 정보. 반복 근력 일정에는 크레아틴의 기능·적합성을 살펴보는 링크를 추가할 수 있다. 필요성·복용량·개인 효과를 판정하지 않는다.
- 최근 7일(선택 날짜 포함) 운동 날짜를 표시한다. 크레아틴 정보 링크의 ‘근력 2일’은 정보 표시 조건이며 임상적 필요 기준이 아니다.
- 11–14시 비식사·비휴식 일정 합집합이 120분 이상이고 식사가 명시되지 않으면 식사 기회 확인을 제안한다. 4시간 이상 학업/업무/과제/성장 일정에는 식사·휴식 안내를 표시한다. 두 기준 모두 UI 휴리스틱이며 결핍·결식 판정 기준이 아니다.
- 화면 작업이 명시된 제목에는 눈 관리 안내를 제공한다. 수업/업무라는 이유만으로 화면 사용을 추정하지 않는다.
- 첫 3개 가이드 이후 항목은 펼쳐 본다. 빈 결과를 영양제로 채우지 않는다.

## 최소 질문과 저장

- 각 카드에서 사용자가 ‘추천 구체화’를 누르면 한 문항을 표시한다. 단백질 식품 준비, 식사 기회, 장시간/다한 발한 예정만 상황별로 확인한다.
- 답변은 `nutrition.scheduleChecks`에 날짜·가이드 종류·일정 맥락 지문과 함께 최대 90건 저장한다. 일정 내용/시간/종류가 달라지면 이전 답변을 자동 적용하지 않는다.
- `unknown`은 미확인으로 보존한다. 당일 단백질 준비 답변으로 평소 proteinIntake나 reviewed, 알레르기·안전 확인을 바꾸지 않는다.
- 운동 종류는 `nutrition.exerciseModes`에 최대 180개 저장하며 수정 가능하다.
- 기존 프로필은 두 배열이 없어도 Zod 기본값으로 복원된다. `/api/state`의 기존 인증·동시성 제어·Neon 저장을 사용한다.

## 제품과 근거

성분 상세의 기존 allergy/safety/current-product hold를 유지한다. 일정에서 식품 섭취량, 영양소 결핍, 보충제 필요성, 투여량을 만들지 않는다. 실제 SKU 라벨·가격·재고 API는 연결하지 않았다. iHerb는 기존 유형 검색 연결이며 구매나 복용으로 기록하지 않는다.

가이드에 NIH ODS 운동 영양제/식사 FAQ, NEI 안구건조 자료 제목을 표시하고 펼쳐서 원문을 연다. 이 자료가 서비스의 일정 분석 휴리스틱을 임상 검증했다고 표시하지 않는다.

## 검증

`tests/schedule-nutrition.test.tsx`: 무설문 진입, 반복/제외/야간/미진행, 휴식·중복 시간, 카테고리 오분류, 근력과 경량 운동 구분, 맥락 변경, 미확인 유지, 기본 이벤트, 미동의, SSR, 계정 저장 핸들러 왕복 검증.
