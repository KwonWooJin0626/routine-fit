# 활동 구체화 질문 파이프라인

- 진입: 홈 ‘루틴 구체화 시작’ / 설정 / 계획표 ‘활동에 맞춘 루틴 구체화’. 기존 기초 설문은 재사용하며 필수 재설문 없음.
- 두 경로: 루틴부터 시작 / 일정부터 시작. 일정이 없으면 계획표로 이동하거나 루틴부터 전환 가능.
- 처음에는 최대 두 분야 활성화. 이전에 확정한 다른 분야 설정은 비활성 상태로 보관.
- 분야별 목표 → 최근 상태 → 활동일 하루 시간 → 주간 시간 → 분야별 기본 질문 → 추천 후보 → 해당 활동만 추가 질문 → 요일 → 실행 시점 → 확인.
- 분야: 운동, 공부, 독서, 외국어, 기술·커리어, 휴식·음악, 생활 정리. 후보 3개씩 페이지 전환. 질문·선택지·활동은 lib/activity-catalog.ts에서 관리.
- 운동: 장소·관심 운동 → 후보 → 경험·불편한 동작·기구·소음·준비 시간. 제한·불확실성이 있으면 실행 확정 대신 준비 활동 선택. 신체 상태의 진단이나 운동 효과 보장 없음.
- 하루 목표는 활동일의 희망 상한. 주간 목표를 선택 요일에 분배하고 일일 상한·최소 5분에 맞지 않으면 사용자가 조정. 입력 출처 self / proposal / planner / none 보관.
- 계획표 시간은 운동/학업/휴식 큰 카테고리의 예정 분량. 실제 수행으로 간주하지 않음. 운동 블록이 있으면 새 운동 시간을 중복 배치하지 않고 기존 일정 확인으로 연결.
- 하루 전체 새 루틴 시간 예산 5~240분, 활동 하나의 목표는 5~120분. 분야들이 시간 예산을 공유하고 운동 이동·준비 시간을 추가 확보. 계획표에는 수면·식사·이동·고정 일정·부담을 함께 고려.
- 정밀화 저장 후 실제 계정 저장 API + 기존 revision CAS 사용. answers.activities는 optional이며 기존 계정/기록·수동 루틴은 보존. JSON 저장이므로 DB 마이그레이션 없음.
- 당일 체크는 에너지·시간·새 불편·오늘 방식 4단계. 장기 선호와 주간 목표는 자동 변경하지 않음.
- 완료·일부·어려움 이후 선택적 피드백/실제 시간 기록. 미입력은 null이고 예정 시간을 실적으로 복사하지 않음. 완료/수동 루틴 및 실제 시간은 재생성 후 유지.
- 과거의 시간/난이도 피드백은 다음 새 추천의 분량을 축소. 싫음/환경 변경은 사용자에게 활동 수정 경로를 안내하며 동의 없이 다른 활동으로 교체하지 않음.
- 계획표가 없는 경우 실행 상황을 선택. 계획표가 있는 경우 ‘빈 시간에 배치’를 고르면 core에서도 가능한 시각을 안내. 주간 목표는 활동 요일에 반영되고 주간 예정 계획표에 자동 삽입하지 않음.
