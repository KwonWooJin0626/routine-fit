# ROUTINE FIT

짧은 질문으로 작은 실천을 시작하고, 일정과 실행 기록으로 루틴을 조정하는 자기개발 React 웹서비스입니다.
기존 화면·추천 엔진·주간/하루 계획 기능을 Next.js로 이전하고, Clerk 인증과 Neon Postgres 계정별 저장을 연결했습니다.

서비스: [routine-fit-seven.vercel.app](https://routine-fit-seven.vercel.app/)

GitHub `main` 브랜치는 Vercel 프로젝트에 연결되어 변경 시 자동 배포됩니다.

## 프로필 메뉴 · 2026-10-28

상단과 왼쪽 아래의 프로필 아이콘에서 설정·기초 프로필 수정·데이터 내려받기·초기화·로그아웃을 이용할 수 있습니다. 메뉴는 키보드 방향키·Esc와 바깥 클릭을 지원합니다. 초기화는 삭제 범위를 확인한 뒤 실행하며, 로그인 계정은 유지하고 첫 질문으로 돌아갑니다. 체험 모드에서는 체험 데이터만 초기화하거나 체험을 종료합니다.

## 2026-10-27 개편

- 기초 질문은 버튼 중심의 한 화면 구성으로 제공하며, 키·몸무게는 선택 입력입니다.
- 질문 후 기본 루틴을 즉시 제공하고 목표·가능 시간·집중 시간·실천 장벽은 선택적으로 추가합니다.
- 계획표 작성 시 예정 일정 기준 생활패턴 분석이 열립니다. 실행 체크와 예정 시간을 구분합니다.
- 오늘의 컨디션 수정 후 오늘의 루틴으로 이동합니다. 영양·InBody 등록은 선택 기능입니다.
- 아침·저녁 자체 작성 글귀, 선택적 한 줄 회고, 웹 취침·기상 체크인과 실제 시각 수정 기능을 제공합니다.
- Resend 연결 코드는 준비되어 있으며, 발송 서비스·발신 도메인·예약 실행 설정 전에는 메일을 보내지 않습니다.
- 기존 기록은 보존합니다. 새 범위 응답을 임의의 정확한 숫자·건강 점수·영양소 결핍으로 환산하지 않습니다.

상세 흐름·데이터 의미·메일 설정은 [개편 문서](docs/self-development-flow.md)를 참고하세요.

- 직접 만드는 루틴, 추천 루틴 선택, 완료 체크와 주간 리포트
- 핵심 루틴 / 하루 전체 계획 모드, 주간 고정 일정과 날짜별 일정, 다른 날짜 루틴 미리보기
- 카테고리별 블록 라이브러리, 드래그 배치, 연결된 일정 일괄 수정·삭제, 전체/정리 시간표
- 한 화면씩 답하는 오늘 체크인, 기본 체크만으로 끝내거나 예정 활동 추가
- 일정 발생 날짜별 완료·부분 진행·미진행·취소와 수행 당시 스냅샷, 건강 루틴과 분리된 주간 수행 기록
- 19종 영양소·보충 성분의 역할·효과·한계·출처, 식단 기반 최대 5개 우선 검토 후보 (근거 부족 시 0개)
- 음식·섭취 프로필, 원료 필터, 단일·복합 제품 선호·장단점, WPC/WPI/식물성 분기, iHerb 유형 검색
- InBody 수치 수동 등록, 선택적 이미지 OCR
- Clerk 로그인·로그아웃, Neon 저장·복원, JSON 내보내기·이전 파일 가져오기

## 기술 구조

React 19 + TypeScript → Next.js 16 App Router → Clerk 세션 검증 → Drizzle ORM / pg → Neon Postgres

Vercel Functions와 DB는 Singapore 리전을 사용합니다. 운영 DB와 개발/미리보기 DB는 분리되어 있습니다.
DB 연결은 TLS 인증서·호스트 이름 검증(`sslmode=verify-full`)을 명시합니다.
추천은 기존 규칙 기반 엔진이며, LLM 호출이나 영양 결핍 진단을 구현한 것은 아닙니다.

## 로컬 실행

Node.js 24.x와 npm이 필요합니다.

```sh
npm ci
vercel link
vercel env pull .env.local --environment=development
npm run db:migrate
npm run dev
```

`vercel link`에서는 본인이 소유한 올바른 팀·프로젝트를 선택하세요. 개발 서버 주소는 `http://localhost:3000`입니다.
인증키 및 DB 연결은 Vercel Marketplace에서 연결한 Clerk / Neon의 환경변수를 사용합니다.
별도 설정 시 `.env.example`의 변수명만 참고하고, 실제 값은 로컬 또는 플랫폼의 비밀 환경변수에 입력하세요.

| 변수 | 용도 |
| --- | --- |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk 공개 인증 설정 |
| `CLERK_SECRET_KEY` | 서버 전용 Clerk 인증키 |
| `DATABASE_URL` | 서버 실행용 pooled 연결 |
| `DATABASE_URL_UNPOOLED` | 스키마 마이그레이션용 direct 연결 |
| `GOOGLE_VISION_API_KEY` | 선택적 OCR 키. 없으면 수동 입력 사용 |

`db:migrate`는 `.env.local`의 대상 DB에 적용합니다. 운영 적용은 대상·마이그레이션을 먼저 검토하고 별도로 실행하세요.
앱 빌드가 운영 DB 마이그레이션을 자동 실행하지 않도록 분리했습니다.

## 영양 가이드의 범위

GPT/LLM은 연결하지 않습니다. 제품 판매 문구가 아닌 NIH ODS·NCCIH 등의 성분 자료를 검토한 정적 데이터와 규칙으로 설명합니다. 성분 자료는 `lib/nutrition.ts`, 사용자 확인 정보는 `lib/nutrition-profile.ts`에 정의합니다.

추천 후보는 결핍 진단·처방이나 동시 복용 목록이 아닙니다. 음식 원료·자유 입력·복용약·질환·기존 영양제 등 위험·불확실성은 보수적으로 처리하며, 개인화 상품 추천을 보류할 수 있습니다. 동일 프로필을 루틴의 식품 안내에도 적용합니다. 제품별 실제 라벨·제공량이 없어 영양소 총량이나 안전성을 계산했다고 표시하지 않습니다.

iHerb 공식 카탈로그·성분표·가격·재고 API 권한은 미확인입니다. 현재 외부 링크는 명시적으로 **유형 검색**이며, 조건에 적합하다고 검증된 실제 상품 추천이 아닙니다. 정식 상품 비교는 승인된 피드/재사용 권한과 SKU별 라벨 검토 후 별도로 연결해야 합니다. 조회·계획·클릭을 실제 섭취·구매로 기록하지 않습니다.
챕터 전환 때만 세로 스크롤을 초기화하며 입력·체크·상세 펼치기에서는 위치를 유지합니다. 팝업은 팝업 내부를, 메뉴·계획 단계는 문서도 함께 초기화합니다.
실제 Clerk 개발 세션으로 API → Neon 저장/복원·계정 격리·CAS·같은 출처 검증·루틴 생성을 확인했습니다.
배포 환경에서도 Clerk 세션 → Vercel API → 운영용 Neon DB 저장·복원을 합성 계정으로 확인했습니다.
검증용 합성 계정과 기록은 검증 후 삭제했습니다. 사용자의 실제 Gmail 로그인/가입 완료는 별도 확인이 필요합니다.

개발 통합 검증은 로컬 서버와 별도 개발 DB, `.env.production.local`이 준비된 경우에만 명시적으로 실행합니다:

```sh
node --env-file=.env.local scripts/verify-integration.mjs
```

이 스크립트는 Clerk 개발 인스턴스에서만 합성 계정을 만들고 자신이 만든 계정/기록만 정리합니다.
운영 의존성 감사는 취약점 0개입니다. 개발 전용 Drizzle Kit의 하위 esbuild 관련 moderate 경고는 남아 있으며,
해당 도구의 외부 공개 개발 서버는 실행하지 않습니다. 강제 다운그레이드는 적용하지 않았습니다.

## 기존 데이터 이전

기존 Sites 서비스는 수정하거나 중단하지 않았습니다. 새 인증 계정은 기존 ChatGPT 계정과 자동으로 연결하지 않습니다.

1. 기존 서비스에 본인 계정으로 로그인해 설정에서 JSON을 내보냅니다.
2. 새 서비스에 로그인하고 `/import`를 엽니다.
3. 대상 계정과 파일 요약을 확인하고 건강정보 이전에 동의한 뒤 가져옵니다.
4. 새 서비스에서 루틴·계획·기록이 복원됐는지 확인합니다.

새 계정에 이미 저장된 데이터가 있으면 가져오기를 차단합니다. 이메일 일치만으로 데이터 소유권을 추정하지 않습니다.
내보낸 파일에는 건강정보가 포함될 수 있으므로 GitHub에 커밋하거나 공유하지 마세요.

## 배포와 운영 주의

- Vercel 팀 `k53952684-7853`, 프로젝트 `routine-fit`을 사용합니다. 배포 전 `vercel project inspect --non-interactive`로 확인하세요.

- 현재 Clerk 키는 **개발 인스턴스**입니다. 테스트/MVP용이며 실제 운영은 도메인과 Clerk production 인스턴스 설정 후 전환해야 합니다.
- Clerk 운영 인스턴스 전환 시 개발 사용자 ID와 달라질 수 있으므로 계정별 데이터 이전 계획도 필요합니다.
- OCR API 키는 아직 별도로 구성해야 합니다. InBody 수동 입력은 키 없이 사용 가능합니다.
- iHerb 연동은 외부 구매 링크이며 결제 API나 공식 제휴가 구현됐다는 의미가 아닙니다.
- 공개 Git에는 소스·스키마·합성 테스트만 포함합니다. 환경변수, 인증 토큰, 사용자 건강정보와 원본 이미지는 제외합니다.

서비스는 생활습관 관리를 위한 참고 정보를 제공합니다. 질병 진단·영양 결핍 확정·처방을 제공하지 않으며,
복용 약·질환·임신 등 안전 확인이 필요한 경우 전문가 상담이 우선입니다.

### 2026-10-28 · 요일별 블록 시간 선택
- 보관함 카테고리 + / 저장 블록 제목 → 전체 주간 시간표에서 여러 시간 드래그 → 세부 설정 → 묶음 저장. 상세 펼치기는 별도 화살표로 유지.
- 요일마다 다른 시작·종료 시각, 같은 날 여러 구간, 개별 날짜/시간 조정·선택 취소, 공통 제목·장소·할 일·부담·피로·색상 설정.
- 고정 일정은 선택 날짜부터 해당 요일마다 반복, 날짜별 일정은 선택 날짜만 저장. 동일 groupId로 기존 전체 수정/제거 기능과 연결.
- 모바일·키보드는 날짜/시간 직접 추가 가능. 자정 종료·익일 종료 및 휴식 간격 이동 지원. 겹침·종료일·개수 제한을 전체 검증한 뒤 기존 저장 API로 한 번에 저장(부분 저장 없음).

### 2026-10-31 · 분야별 활동 구체화
- 홈·설정·계획표에서 ‘루틴 구체화’ 시작. 루틴부터 / 일정부터 두 경로, 관심 분야 최대 2개 선택, 기존 기초 응답 재사용.
- 목표·현재 상태·활동일 하루/주간 시간 → 활동 후보 먼저 → 선택 활동의 환경·경험·제약 질문 → 요일·시점 → 확정. 7개 분야, 26개 규칙 기반 활동 후보.
- 주간 목표와 요일/하루 상한 불일치 시 사용자가 조정. 모든 분야가 당일 시간 예산 공유. 계획표 운동의 중복 추가 방지, 이동·준비시간 확보, core 모드의 계획표 빈 슬롯 시각 안내.
- 당일 체크 4단계로 분량 조정. 완료·수동 루틴과 실제 시간 보존. 선택적 시간/난이도 피드백은 다음 분량에 반영.
- 예정·목표와 명시 입력한 실제 시간을 구분. 미입력은 null. 기존 JSON payload에 optional 필드로 저장하며 인증·revision CAS 유지, DB 마이그레이션 없음.
- 전체 흐름: docs/activity-question-flow.md. 자동 테스트 126개 + 개발 DB 왕복·계정 분리·CAS 검증.
